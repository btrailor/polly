### Key decisions made today

**Security (locked by @security_audit):**
- Keychain (`expo-secure-store`) for Ed25519 device key — Phase 1. Secure Enclave deferred to Phase 3.
- `NSFileProtectionComplete` set via `app.json` `infoPlist` (OS-level, covers all app data). `react-native-mmkv` v4.3.0 has no native file protection support; `expo-file-system` `setFileProtectionAsync` not available in current SDK.
- MMKV encryption: dedicated randomly-generated 32-byte key, hex-encoded, stored in Keychain under `polly.mmkv.encryptionKey`. Never derived from device key or auth token.
- TOFU: application-layer Phase 1A (gateway sends fingerprint in `auth.ok`). Native TLS inspection deferred to Phase 2.
- `sanitizeForLog()` scrubs all 9 `SECURE_STORE_KEYS` fields + bare cfargotunnel URLs.

**Architecture:**
- `PollyGatewayAdapter` uses SDK-internal `GatewayClient` (from `expo-openclaw-chat`). App-level `GatewayClient` singleton retired (`b650086`) — SDK client is source of truth.
- TOFU fingerprint write lives in `GatewayClient._onOpen()` on `auth.ok`, not in onboarding flow.
- `polly.security.protectionLevel: "standard"` sent in initial `config.patch` on connection.
- `getMMKVEncryptionKey()` sync accessor requires `initMMKVEncryptionKey()` called in app bootstrap before any store init.

**Onboarding:** Manual form only (Phase 1A). Conversational onboarding (Gemini Flash) is Phase 2.
